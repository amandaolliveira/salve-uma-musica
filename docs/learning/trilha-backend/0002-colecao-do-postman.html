Backend 2: The whole Postman collection

Win: import postman/colecao.json, run all 20 requests in one click, see 27 tests pass, and explain what each folder proves. The collection is a graded deliverable. Needs base lesson 3.

1. Import it

In Postman: Import (top left), choose the file postman/colecao.json from the repo. A collection called Salve Uma Música appears. (Postman docs: importing data)

2. The four folders

FolderWhat it proves
1. DeezerGET on the source API: genres, the chart of one genre, one track. The chart request saves the first track's data in variables.
2. Banco - criar coleçõesPUT creates musica and artista (201, or 200 if they exist).
3. Banco - musicaThe whole CRUD: POST (imported and manual), GET (list, filter, by id), PUT, PATCH, DELETE, and the 404 after the DELETE.
4. Banco - artistaPOST and GET on the second collection.

3. The variables

Open the collection and the Variables tab. Some values are fixed, others are filled by scripts while the collection runs.

VariableFilled by
base_url, deezer_urlFixed: http://localhost:8080 and https://api.deezer.com
id_genero, nome_generoFixed: 152 / Rock. Change both to test another genre.
id_deezer, id_artista, titulo_json, nome_artista_json, duracao, url_capa_json, url_foto_jsonThe script of "GET Músicas em alta do gênero", from the first track
id_manualThe script of "POST Inserir música manual", from the Location header

Why titulo_json and not titulo? A title may contain quotes, which would break the JSON body. The script stores JSON.stringify(title) (the title already wrapped in quotes and escaped), and the body uses {{titulo_json}} without quotes around it.

4. Run it

  1. Start the project: docker compose up -d.
  2. In Postman, click the three dots of the collection, then Run collection. Keep the order and click Run. (Postman docs: collection runs)
  3. Expected: 20 requests, all tests passed.

The "POST Inserir música importada" may return 201 or 409. Both pass: 409 just means that song had already been imported by the app.

5. Read one test

Open "DELETE Excluir música manual" and its Scripts (or Tests) tab:

pm.test('Status 204', () => pm.response.to.have.status(204));

A test is a named check that runs after the response arrives. If the status is not 204, the run shows it in red. The next request, "GET Música excluída (404)", checks that the document is really gone.

6. If something fails

What you seeCause
ECONNREFUSED on every database requestContainers not running. docker compose up -d, wait 10 seconds.
401 UnauthorizedThe collection's Authorization tab lost Basic Auth admin / secret.
Only the Deezer folder failsNo internet. The database folders still work, but the imported POST falls back to the default variable values.
"GET Buscar música manual por id" gives 404"POST Inserir música manual" did not run first, so id_manual is empty. Run the whole collection in order.

Backend 2: A coleção inteira do Postman

Objetivo: importar o postman/colecao.json, rodar as 20 requisições com um clique, ver os 27 testes passarem e explicar o que cada pasta prova. A coleção é um item avaliado. Precisa da aula base 3.

1. Importe

No Postman: Import (canto superior esquerdo), escolha o arquivo postman/colecao.json do repositório. Aparece uma coleção chamada Salve Uma Música. (Documentação do Postman: importar dados, em inglês)

2. As quatro pastas

PastaO que prova
1. DeezerGET na API de origem: gêneros, o chart de um gênero, uma faixa. A requisição do chart guarda os dados da primeira faixa em variáveis.
2. Banco - criar coleçõesPUT cria musica e artista (201, ou 200 se já existem).
3. Banco - musicaO CRUD inteiro: POST (importada e manual), GET (lista, filtro, por id), PUT, PATCH, DELETE e o 404 depois do DELETE.
4. Banco - artistaPOST e GET na segunda coleção.

3. As variáveis

Abra a coleção e a aba Variables. Alguns valores são fixos, outros são preenchidos por scripts enquanto a coleção roda.

VariávelPreenchida por
base_url, deezer_urlFixas: http://localhost:8080 e https://api.deezer.com
id_genero, nome_generoFixas: 152 / Rock. Troque as duas para testar outro gênero.
id_deezer, id_artista, titulo_json, nome_artista_json, duracao, url_capa_json, url_foto_jsonO script do "GET Músicas em alta do gênero", a partir da primeira faixa
id_manualO script do "POST Inserir música manual", a partir do cabeçalho Location

Por que titulo_json e não titulo? Um título pode ter aspas, o que quebraria o corpo JSON. O script guarda JSON.stringify(title) (o título já entre aspas e escapado), e o corpo usa {{titulo_json}} sem aspas em volta.

4. Rode

  1. Suba o projeto: docker compose up -d.
  2. No Postman, clique nos três pontos da coleção e depois em Run collection. Mantenha a ordem e clique em Run. (Documentação do Postman: rodar coleções, em inglês)
  3. Esperado: 20 requisições, todos os testes passando.

O "POST Inserir música importada" pode retornar 201 ou 409. Os dois passam: 409 só quer dizer que essa música já tinha sido importada pelo app.

5. Leia um teste

Abra o "DELETE Excluir música manual" e a aba Scripts (ou Tests):

pm.test('Status 204', () => pm.response.to.have.status(204));

Um teste é uma verificação com nome que roda depois que a resposta chega. Se o status não for 204, o resultado aparece em vermelho. A requisição seguinte, "GET Música excluída (404)", confere se o documento sumiu mesmo.

6. Se algo falhar

O que apareceCausa
ECONNREFUSED em toda requisição ao bancoContêineres parados. docker compose up -d e espere 10 segundos.
401 UnauthorizedA aba Authorization da coleção perdeu o Basic Auth admin / secret.
Só a pasta do Deezer falhaSem internet. As pastas do banco continuam funcionando, mas o POST da importada usa os valores padrão das variáveis.
"GET Buscar música manual por id" dá 404O "POST Inserir música manual" não rodou antes, então id_manual está vazio. Rode a coleção inteira, em ordem.
