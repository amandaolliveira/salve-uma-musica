Database 1: Getting your branch

Win: have the project on your computer, on the branch banco-de-dados, with Git knowing who you are. Your commits in this track go to this branch only; the group merges it into master later.

1. What is a branch?

A branch is a separate line of commits. master has the project as it is today. banco-de-dados starts as a copy of it, and receives only your changes, so you and the frontend colleague never step on each other. Later the branches are merged back into master. (Pro Git: remote branches)

2. Install and check

You need Git and Docker Desktop. Open a terminal (PowerShell on Windows) and check:

git --version
docker --version

Both should print a version number.

3. Get the project and switch to your branch

If you do not have the repository yet:

git clone https://github.com/amandaolliveira/salve-uma-musica.git
cd salve-uma-musica

If you already have it, go into its folder and download what is new:

git fetch

Then, in both cases:

git checkout banco-de-dados
git branch

Expected: branch 'banco-de-dados' set up to track 'origin/banco-de-dados' (or Switched to branch), and git branch shows * banco-de-dados. The asterisk marks the branch you are on.

4. Tell Git who you are (once per computer)

git config --global user.name "Your Name"
git config --global user.email "the-email-of-your-github-account"

Every commit carries this name and email. The assignment checks that every member has commits, so use the email of your GitHub account.

5. The cycle you will use in lesson 5

git branch                        am I on banco-de-dados?
git status                        what changed?
git add docs/estrutura_banco.md   choose what goes in the next commit
git commit -m "message"           save a snapshot, with a message
git push origin banco-de-dados    send your commits to YOUR branch on GitHub
git pull origin banco-de-dados    bring the newest commits of your branch

(Pro Git: recording changes) The first git push opens a browser window to log into GitHub. To push, your GitHub account must be a collaborator of the repository; the repository owner adds you in Settings → Collaborators.

6. Two rules

  • Before working, run git branch and confirm the asterisk is on banco-de-dados. Never commit on master.
  • Do not merge anything yourself. The group merges the branches together, at the end.

7. If something goes wrong

MessageWhat to do
pathspec 'banco-de-dados' did not matchRun git fetch and try again. If it still fails, the branch was not pushed to GitHub yet: ask the backend colleague to push it.
Please tell me who you areDo section 4.
Permission denied or 403 on pushYour GitHub account is not a collaborator yet. Ask the repository owner.
Your local changes would be overwritten on checkoutYou changed files on another branch. Run git status; to throw those changes away, git restore .

To open these lessons at any time: open the file docs/learning/index.html of the repository in the browser (double-click it).

Banco 1: Pegando sua branch

Objetivo: ter o projeto no seu computador, na branch banco-de-dados, com o Git sabendo quem você é. Os seus commits desta trilha vão só para essa branch; o grupo mescla ela na master depois.

1. O que é uma branch?

Uma branch é uma linha separada de commits. A master tem o projeto como está hoje. A banco-de-dados começa como uma cópia dela e recebe só as suas mudanças, então você e o colega do frontend nunca atrapalham um ao outro. Depois as branches são mescladas (merge) de volta na master. (Pro Git: branches remotos)

2. Instale e confira

Você precisa do Git e do Docker Desktop. Abra um terminal (PowerShell no Windows) e confira:

git --version
docker --version

Os dois devem mostrar um número de versão.

3. Pegue o projeto e troque para a sua branch

Se você ainda não tem o repositório:

git clone https://github.com/amandaolliveira/salve-uma-musica.git
cd salve-uma-musica

Se você já tem, entre na pasta dele e baixe o que há de novo:

git fetch

Depois, nos dois casos:

git checkout banco-de-dados
git branch

Esperado: branch 'banco-de-dados' set up to track 'origin/banco-de-dados' (ou Switched to branch), e o git branch mostra * banco-de-dados. O asterisco marca a branch em que você está.

4. Diga ao Git quem você é (uma vez por computador)

git config --global user.name "Seu Nome"
git config --global user.email "o-email-da-sua-conta-do-github"

Todo commit leva esse nome e e-mail. O trabalho confere se todos os integrantes têm commits, então use o e-mail da sua conta do GitHub.

5. O ciclo que você vai usar na aula 5

git branch                        estou na banco-de-dados?
git status                        o que mudou?
git add docs/estrutura_banco.md   escolha o que vai no próximo commit
git commit -m "mensagem"          salve uma versão, com uma mensagem
git push origin banco-de-dados    envie seus commits para a SUA branch no GitHub
git pull origin banco-de-dados    traga os commits mais novos da sua branch

(Pro Git: gravando alterações) O primeiro git push abre uma janela do navegador para entrar no GitHub. Para conseguir enviar, a sua conta do GitHub precisa ser colaboradora do repositório; quem é dono do repositório adiciona você em Settings → Collaborators.

6. Duas regras

  • Antes de trabalhar, rode git branch e confira se o asterisco está na banco-de-dados. Nunca faça commit na master.
  • Não faça merge de nada sozinho. O grupo mescla as branches junto, no fim.
