Database 3: The database in Docker

Win: explain every line of the mongodb and restheart services in docker-compose.yml, and prove with a count that the data survives down but not down -v. In the assignment, "database in Docker" is your role.

1. The two services, line by line

(Docker docs: services)

services:
  mongodb:
    image: mongo:7                 # official MongoDB image, version 7
    restart: unless-stopped        # restarts by itself if it crashes
    ports:
      - "27017:27017"              # your computer : container. Only Compass uses it;
                                   # the app talks to RESTHeart, not to MongoDB directly
    volumes:
      - dados-mongo:/data/db       # named volume mounted where MongoDB writes its files

  restheart:
    image: softinstigate/restheart:8
    depends_on:
      - mongodb                    # start MongoDB first
    environment:
      RHO: '/mclient/connection-string->"mongodb://mongodb:27017";/http-listener/host->"0.0.0.0"'
    ports:
      - "8080:8080"                # the HTTP API the app and Postman call

volumes:
  dados-mongo:                     # declares the named volume

Two things in RHO (RESTHeart's settings in one line):

  • mongodb://mongodb:27017: the second mongodb is the service name. Inside Docker's network each service is reachable by its name, like a hostname.
  • http-listener/host->"0.0.0.0": accept connections from outside the container, otherwise localhost:8080 on your computer would not answer.

RESTHeart keeps everything in a database called restheart (its default). /musica in a URL is the collection musica of that database.

2. The named volume

A container's own files disappear when the container is removed. A named volume is storage managed by Docker that outlives the containers (Docker docs: volumes). Compose puts the project name in front of it, so on your machine it is called salve-uma-musica_dados-mongo.

CommandContainersVolume (your data)
docker compose downremovedkept
docker compose down -vremoveddeleted

3. Try it

  1. In the repo folder: docker compose up -d, then docker compose ps. Three services must be running.
  2. Open http://localhost:3000, go to Importar, choose a genre, click Importar. Wait for the green message.
  3. See the volume: docker volume ls. Expected line: local salve-uma-musica_dados-mongo.
  4. Count the songs from inside the MongoDB container: 
    docker compose exec mongodb mongosh --quiet --eval "db.getSiblingDB('restheart').musica.countDocuments()"
    Expected: a number like 100. Write it down.
  5. docker compose down, then docker compose up -d, and run the count again. Same number: the volume kept the data.

Do not run down -v now unless you want to import again. If you do, the count command answers 0 afterwards (the page recreates the collections when you open it).

4. If something goes wrong

MessageWhat to do
port is already allocated for 27017Another MongoDB is running on your computer. Close it, or change the left number (e.g. "27018:27017") and use that port in Compass.
service "mongodb" is not runningRun docker compose up -d first.
error during connect or Cannot connect to the Docker daemonDocker Desktop is closed. Open it and wait until it says it is running.

Banco 3: O banco no Docker

Objetivo: explicar cada linha dos serviços mongodb e restheart do docker-compose.yml, e provar com uma contagem que os dados sobrevivem ao down, mas não ao down -v. No trabalho, "banco no Docker" é o seu papel.

1. Os dois serviços, linha por linha

(Documentação do Docker: services, em inglês)

services:
  mongodb:
    image: mongo:7                 # imagem oficial do MongoDB, versão 7
    restart: unless-stopped        # reinicia sozinho se cair
    ports:
      - "27017:27017"              # seu computador : contêiner. Só o Compass usa;
                                   # o app fala com o RESTHeart, não direto com o MongoDB
    volumes:
      - dados-mongo:/data/db       # volume nomeado montado onde o MongoDB grava os arquivos

  restheart:
    image: softinstigate/restheart:8
    depends_on:
      - mongodb                    # suba o MongoDB primeiro
    environment:
      RHO: '/mclient/connection-string->"mongodb://mongodb:27017";/http-listener/host->"0.0.0.0"'
    ports:
      - "8080:8080"                # a API HTTP que o app e o Postman chamam

volumes:
  dados-mongo:                     # declara o volume nomeado

Duas coisas no RHO (as configurações do RESTHeart em uma linha):

  • mongodb://mongodb:27017: o segundo mongodb é o nome do serviço. Dentro da rede do Docker, cada serviço é encontrado pelo nome, como um endereço.
  • http-listener/host->"0.0.0.0": aceitar conexões de fora do contêiner; sem isso, o localhost:8080 do seu computador não responderia.

O RESTHeart guarda tudo em um banco chamado restheart (o padrão dele). O /musica de uma URL é a coleção musica desse banco.

2. O volume nomeado

Os arquivos de dentro de um contêiner somem quando ele é removido. Um volume nomeado é um armazenamento gerenciado pelo Docker que dura mais que os contêineres (Documentação do Docker: volumes, em inglês). O Compose coloca o nome do projeto na frente, então no seu computador ele se chama salve-uma-musica_dados-mongo.

ComandoContêineresVolume (seus dados)
docker compose downremovidosmantido
docker compose down -vremovidosapagado

3. Experimente

  1. Na pasta do repositório: docker compose up -d e depois docker compose ps. Três serviços precisam estar rodando.
  2. Abra http://localhost:3000, vá em Importar, escolha um gênero e clique em Importar. Espere a mensagem verde.
  3. Veja o volume: docker volume ls. Linha esperada: local salve-uma-musica_dados-mongo.
  4. Conte as músicas de dentro do contêiner do MongoDB: 
    docker compose exec mongodb mongosh --quiet --eval "db.getSiblingDB('restheart').musica.countDocuments()"
    Esperado: um número como 100. Anote.
  5. docker compose down, depois docker compose up -d, e rode a contagem de novo. Mesmo número: o volume guardou os dados.

Não rode down -v agora, a não ser que queira importar de novo. Se rodar, a contagem responde 0 depois (a página recria as coleções quando você a abre).
