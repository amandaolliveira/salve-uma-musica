## Justificativa

O nome do artista fica **embutido** na música (`artista.nome_artista`), porque ele aparece
em toda listagem e em todo round do jogo. Assim uma leitura traz tudo, sem precisar de JOIN.

O resto do artista (a foto) fica na coleção `artista`, **referenciado** pelo `id_artista`.
Um artista tem várias músicas e a foto não é usada pelas telas, então não vale copiar em cada música.

O custo: se um artista mudar de nome, todas as músicas dele precisam ser atualizadas.
Como isso é raro, vale a pena.

O `_id` das músicas importadas é o id do Deezer. Assim, importar o mesmo gênero de novo
não duplica nada: o RESTHeart responde 409 e a música é ignorada.

## Verificação

Conferido no MongoDB Compass em 07/11/2026 (banco `restheart`):

- `musica`: 100 documentos (1 gênero importado: Rock)
- `artista`: 71 documentos
- Filtro `{ vitorias: { $gt: 0 } }`: 2 documentos, depois de 2 partidas
- Um documento tem `duracao` e `vitorias` (números), `criado_em` (data) e `artista` (objeto embutido)

The numbers above are only an example. Use the ones you saw.

4. Send it to your branch, step by step (final)

Run each command in the terminal, in the repository folder, and compare with the expected result before going to the next one.

  1. Confirm you are on your branch. 
    git branch
    Expected: * banco-de-dados. If the asterisk is on another branch, run git switch banco-de-dados first (your changes come along).
  2. See what changed. 
    git status
    Expected: modified: docs/estrutura_banco.md in red, under "Changes not staged for commit".
  3. Choose what goes in the commit. 
    git add docs/estrutura_banco.md
    Run git status again: the same file(s) now appear in green, under "Changes to be committed".
  4. Save the commit. 
    git commit -m "docs: justificativa e verificação do modelo"
    Expected: a line starting with [banco-de-dados followed by a code and your message. The name in brackets must be your branch.
  5. Send it to your branch on GitHub. 
    git push origin banco-de-dados
    Expected, at the end: banco-de-dados -> banco-de-dados. The first push may open the browser to log into GitHub.
  6. Check on GitHub. Open the repository page, switch the branch selector (top left) to banco-de-dados and click the commit history: your commit is there, with your name.

Always write the branch name in the push: git push origin banco-de-dados. Never run git push origin master; master only changes when the group merges the branches.

If you seeDo this
nothing to commitThe file was not saved in the editor. Save it and start again from step 2.
[master ...] in step 4, or Everything up-to-date in step 5 with nothing new on GitHubThe commit went to the wrong branch. Run git switch banco-de-dados, then git cherry-pick master (copies that last commit to your branch), then git push origin banco-de-dados. Do not push master.
rejected ... fetch firstSomeone pushed to your branch before you. Run git pull origin banco-de-dados, then repeat step 5.
Permission denied or 403Your GitHub account is not a collaborator yet. Ask the repository owner.

4. Envie para a sua branch, passo a passo (final)

Rode cada comando no terminal, na pasta do repositório, e compare com o resultado esperado antes de ir para o próximo.

  1. Confirme que você está na sua branch. 
    git branch
    Esperado: * banco-de-dados. Se o asterisco estiver em outra branch, rode antes git switch banco-de-dados (as suas mudanças vêm junto).
  2. Veja o que mudou. 
    git status
    Esperado: modified: docs/estrutura_banco.md em vermelho, em "Changes not staged for commit".
  3. Escolha o que vai no commit. 
    git add docs/estrutura_banco.md
    Rode git status de novo: o(s) mesmo(s) arquivo(s) agora aparece(m) em verde, em "Changes to be committed".
  4. Salve o commit. 
    git commit -m "docs: justificativa e verificação do modelo"
    Esperado: uma linha começando com [banco-de-dados , seguida de um código e da sua mensagem. O nome entre colchetes precisa ser a sua branch.
  5. Envie para a sua branch no GitHub. 
    git push origin banco-de-dados
    Esperado, no fim: banco-de-dados -> banco-de-dados. O primeiro push pode abrir o navegador para entrar no GitHub.
  6. Confira no GitHub. Abra a página do repositório, troque o seletor de branch (no canto superior esquerdo) para banco-de-dados e clique no histórico de commits: o seu commit está lá, com o seu nome.

Sempre escreva o nome da branch no push: git push origin banco-de-dados. Nunca rode git push origin master; a master só muda quando o grupo mescla as branches.
