3. Likely questions

Database

  • Relational vs document database? A table has fixed columns and relations use JOIN. A document is JSON that can carry objects and lists inside it, and documents in the same collection may have different fields.
  • Why is the artist name inside the song? It appears in every list and every round, so it comes with the song in one read. The photo is rarely needed, so it stays in artista.
  • And if the artist changes name? Every song by that artist would need updating. That is the cost of embedding, and it is acceptable because it is rare.
  • Why do the data survive a restart? They live in the named volume dados-mongo, outside the container. Only down -v deletes it.
  • What is _etag? A field RESTHeart adds to each document to mark its version. We do not use it.

Backend

  • PUT vs PATCH? PUT replaces the whole document; PATCH changes only the fields sent (or uses operators like $inc).
  • Why does the import ignore 409? The song id is Deezer's id, so 409 means "already saved". That is how importing twice never duplicates.
  • Why ?id_type=NUMBER? The _id is a number, and without it RESTHeart looks for the text, answering 404.
  • Why the nginx proxy? Deezer does not send Access-Control-Allow-Origin, so the browser blocks a direct fetch.
  • Why check res.ok? fetch does not throw on 404 or 500.

Frontend

  • How does the dashboard update by itself? After every POST, PUT, PATCH or DELETE, the app lists the songs again (recarregar) and recalculates everything.
  • How does the layout change on a phone? A media query (@media (max-width: 600px)) changes a few rules below that width; the grids adapt on their own with auto-fit.
  • What does :ro do in the volume? The container can read the files but not change them.
  • Who calls localhost:8080? The browser, not the nginx container.

3. Perguntas prováveis

Banco

  • Banco relacional x banco de documentos? Uma tabela tem colunas fixas e as relações usam JOIN. Um documento é um JSON que pode ter objetos e listas dentro, e documentos da mesma coleção podem ter campos diferentes.
  • Por que o nome do artista fica dentro da música? Ele aparece em toda listagem e em todo round, então vem junto com a música em uma leitura só. A foto quase nunca é usada, então fica em artista.
  • E se o artista mudar de nome? Todas as músicas dele teriam que ser atualizadas. É o custo de embutir, e vale a pena porque é raro.
  • Por que os dados sobrevivem a um reinício? Eles ficam no volume nomeado dados-mongo, fora do contêiner. Só o down -v apaga.
  • O que é o _etag? Um campo que o RESTHeart coloca em cada documento para marcar a versão. Não usamos.

Backend

  • PUT x PATCH? O PUT substitui o documento inteiro; o PATCH altera só os campos enviados (ou usa operadores como $inc).
  • Por que a importação ignora o 409? O id da música é o id do Deezer, então 409 significa "já está salva". É assim que importar duas vezes nunca duplica.
  • Por que ?id_type=NUMBER? O _id é um número, e sem isso o RESTHeart procura o texto e responde 404.
  • Por que o proxy do nginx? O Deezer não envia Access-Control-Allow-Origin, então o navegador bloqueia um fetch direto.
  • Por que conferir res.ok? O fetch não lança erro em 404 ou 500.

Frontend

  • Como o painel se atualiza sozinho? Depois de todo POST, PUT, PATCH ou DELETE, o app lista as músicas de novo (recarregar) e recalcula tudo.
  • Como o layout muda no celular? Uma media query (@media (max-width: 600px)) muda algumas regras abaixo dessa largura; os grids se ajustam sozinhos com auto-fit.
  • O que o :ro faz no volume? O contêiner pode ler os arquivos, mas não alterá-los.
  • Quem chama o localhost:8080? O navegador, não o contêiner do nginx.
