Lesson 4: The frontend and the Deezer proxy

Win: explain why the browser cannot call Deezer directly, how the nginx container fixes it, and follow one import through app.js. Needs lessons 1 to 3 done.

1. The third service

The docker-compose.yml now has a frontend service (nginx). It serves the frontend/ folder at http://localhost:3000 and is what earns the +1.0 extra point.

frontend:
  image: nginx:alpine
  ports:
    - "3000:80"                                    # host 3000 -> nginx 80
  volumes:
    - ./frontend:/usr/share/nginx/html:ro          # the site files
    - ./nginx/default.conf:/etc/nginx/conf.d/default.conf:ro   # the proxy

The fetch calls in app.js still point to http://localhost:8080, because the request is made by your browser, not by the container.

2. CORS: the rule Postman ignores

A page from one origin (here http://localhost:3000) may only read a response from another origin if that server answers with the header Access-Control-Allow-Origin. Otherwise the browser blocks it. (MDN: CORS)

  • RESTHeart sends the header, so the page can talk to it directly.
  • Deezer does not. A fetch('https://api.deezer.com/genre') from the page fails, even though the same URL opens fine in the address bar (opening a page is not a fetch) and in Postman (which has no CORS rule).

3. The proxy

If the page calls its own origin, there is no CORS check. So nginx answers /deezer/... and forwards it to Deezer (nginx/default.conf, nginx docs: proxy module):

location /deezer/ {
    set $deezer https://api.deezer.com;
    rewrite ^/deezer/(.*)$ /$1 break;   # /deezer/genre -> /genre
    proxy_pass $deezer;
    ...
}

In app.js that is the line const DEEZER = '/deezer';. It is also why the import only works through the container: opening index.html straight from disk has no nginx behind it.

4. Follow one import in app.js

importar(idGenero, nomeGenero)
  deezer('/chart/152/tracks?limit=100')   GET through the proxy
  documentoDaFaixa(faixa, 'Rock')         Deezer track -> our document
  inserir('artista', ...)                 POST, 201 new or 409 already there
  inserir('musica', ...)                  POST, 201 new or 409 already there
recarregar()
  listarMusicas()                         GET /musica?pagesize=1000
  renderizarLista(), renderizarPainel()   list and dashboard recalculated

Requests to the database go through requisicao(), which checks res.ok (inserir() checks the status itself, because 409 is expected there). That check is needed because fetch does not throw on 404 or 500, only on network failures. When it fails, the message shows the HTTP status.

5. Try it

With docker compose up -d running:

  1. Open http://localhost:3000/deezer/genre. You get Deezer's JSON through nginx.
  2. See the missing header yourself. In PowerShell: 
    curl.exe -s -D - -o NUL -H "Origin: http://localhost:3000" https://api.deezer.com/genre
    There are several Access-Control-... lines, but no Access-Control-Allow-Origin.
  3. Open http://localhost:3000, press F12, go to Console and run each line: 
    await fetch('https://api.deezer.com/genre')                 // CORS error
(await (await fetch('/deezer/genre')).json()).data.length   // a number

Aula 4: O frontend e o proxy do Deezer

Objetivo: explicar por que o navegador não consegue chamar o Deezer direto, como o contêiner nginx resolve isso, e seguir uma importação pelo app.js. Precisa das aulas 1 a 3 concluídas.

1. O terceiro serviço

O docker-compose.yml agora tem um serviço frontend (nginx). Ele serve a pasta frontend/ em http://localhost:3000 e é o que garante o ponto extra (+1,0).

frontend:
  image: nginx:alpine
  ports:
    - "3000:80"                                    # host 3000 -> nginx 80
  volumes:
    - ./frontend:/usr/share/nginx/html:ro          # os arquivos do site
    - ./nginx/default.conf:/etc/nginx/conf.d/default.conf:ro   # o proxy

Os fetch do app.js continuam apontando para http://localhost:8080, porque quem faz a requisição é o seu navegador, não o contêiner.

2. CORS: a regra que o Postman ignora

Uma página de uma origem (aqui http://localhost:3000) só pode ler a resposta de outra origem se esse servidor responder com o cabeçalho Access-Control-Allow-Origin. Senão o navegador bloqueia. (MDN: CORS)

  • O RESTHeart envia o cabeçalho, então a página fala com ele direto.
  • O Deezer não envia. Um fetch('https://api.deezer.com/genre') a partir da página falha, mesmo que a mesma URL abra normalmente na barra de endereço (abrir uma página não é um fetch) e no Postman (que não tem a regra de CORS).

3. O proxy

Se a página chama a própria origem, não há verificação de CORS. Então o nginx responde /deezer/... e repassa para o Deezer (nginx/default.conf, documentação do nginx: proxy, em inglês):

location /deezer/ {
    set $deezer https://api.deezer.com;
    rewrite ^/deezer/(.*)$ /$1 break;   # /deezer/genre -> /genre
    proxy_pass $deezer;
    ...
}

No app.js isso é a linha const DEEZER = '/deezer';. É também por isso que a importação só funciona pelo contêiner: abrindo o index.html direto do disco não há nginx por trás.

4. Siga uma importação no app.js

importar(idGenero, nomeGenero)
  deezer('/chart/152/tracks?limit=100')   GET pelo proxy
  documentoDaFaixa(faixa, 'Rock')         faixa do Deezer -> nosso documento
  inserir('artista', ...)                 POST, 201 novo ou 409 já existe
  inserir('musica', ...)                  POST, 201 novo ou 409 já existe
recarregar()
  listarMusicas()                         GET /musica?pagesize=1000
  renderizarLista(), renderizarPainel()   lista e painel recalculados

As requisições ao banco passam pela requisicao(), que confere res.ok (a inserir() confere o status ela mesma, porque ali o 409 é esperado). Essa conferência é necessária porque o fetch não lança erro em 404 ou 500, só em falha de rede. Quando falha, a mensagem mostra o status HTTP.

Com o docker compose up -d rodando:

  2. Veja o cabeçalho que falta. No PowerShell: 
    curl.exe -s -D - -o NUL -H "Origin: http://localhost:3000" https://api.deezer.com/genre
    Aparecem várias linhas Access-Control-..., mas nenhuma Access-Control-Allow-Origin.
  3. Abra http://localhost:3000, aperte F12, vá em Console e rode cada linha:

(await (await fetch('/deezer/genre')).json()).data.length   // um número
