Lesson 3: Your first requests in Postman

Win: build a Postman collection with a request for every HTTP method, read each status code, save a new document's ID in a variable, and compare your work with postman/colecao.json. Needs lessons 1 and 2 done (containers running).

1. Why Postman, in one minute

A browser can only send GET from the address bar. Postman is a form for building any request (method, URL, login, headers, body) and showing the answer clearly (status code, time, JSON). A collection is a saved group of those requests. Exporting it gives a JSON file that anyone can import to repeat your tests. (Postman docs: send your first request) The menu names below may differ a little in your version.

2. Set up the collection once

  1. Create a new collection named Salve Uma Música (treino).
  2. Authorization tab of the collection: type Basic Auth, user admin, password secret. Every request inside will use Inherit auth from parent, so you type the login only once.
  3. Variables tab of the collection: add base_url = http://localhost:8080 and an empty id_manual. In a request you write {{base_url}}/musica/{{id_manual}} and Postman fills the values in.

3. Save an ID from a response (the only scripting you need)

A song added by hand has no Deezer id, so you POST it without _id and MongoDB invents one. RESTHeart returns it in the Location header (look at the response's Headers tab). To reuse it, open the Scripts tab (older versions: Tests) of the POST request below and add:

const location = pm.response.headers.get("Location");
pm.collectionVariables.set("id_manual", location.split("/").pop());

4. The requests

Create these in order. For the body, open the Body tab, choose raw and JSON; Postman then sends the right Content-Type header for you. Click Send and compare the status with the table.

Method  URL                                Body                                            Expect
PUT     {{base_url}}/musica                (none)                                          201 (200 if it exists)
POST    {{base_url}}/musica                { "titulo": "Teste", "duracao": 100,            201
                                             "adicionado_manualmente": true, "vitorias": 0 }
GET     {{base_url}}/musica/{{id_manual}}  (none)                                          200
GET     {{base_url}}/musica?pagesize=20    (none)                                          200
PUT     {{base_url}}/musica/{{id_manual}}  { "titulo": "Teste 2", "duracao": 100 }         200
PATCH   {{base_url}}/musica/{{id_manual}}  { "$inc": { "vitorias": 1 } }                   200
DELETE  {{base_url}}/musica/{{id_manual}}  (none)                                          204

Then GET {{base_url}}/musica/{{id_manual}} once more: it should now be 404. Check what each step did: after the PUT, adicionado_manualmente is gone (PUT replaces the whole document), and the PATCH created vitorias again with the value 1. That is the trap from lesson 2, now visible.

Imported songs use Deezer's number as _id, so a request by id for them needs ?id_type=NUMBER, for example {{base_url}}/musica/518458172?id_type=NUMBER (lesson 2, trap 4).

Warning: 201 does not prove your data was saved. It only means "a document was created". If the Body tab is on none, or on a type other than raw + JSON, the POST still returns 201 but stores an empty document with a generated _id, and every re-send adds another one. After any POST, run the GET and check that your fields (titulo, duracao) are there. If you see documents with only an _id, delete them (DELETE {{base_url}}/musica/<_id>), fix the Body tab, and send the POST again.

5. Compare with the project's collection

The repo already has the full collection in postman/colecao.json (Deezer requests, both collections, every method, and a test on each status). Do not export over it. Instead, choose Import in Postman, pick that file, and compare it with what you built. You can run it all at once with the collection's Run button.

The file includes the login admin / secret. That is fine here, because it is RESTHeart's public default.

Aula 3: Suas primeiras requisições no Postman

Objetivo: montar uma coleção do Postman com uma requisição para cada método HTTP, ler cada código de status, guardar o ID de um documento novo em uma variável e comparar seu trabalho com o postman/colecao.json. Precisa das aulas 1 e 2 concluídas (contêineres rodando).

1. Por que Postman, em um minuto

Um navegador só envia GET pela barra de endereço. O Postman é um formulário para montar qualquer requisição (método, URL, login, cabeçalhos, corpo) e mostrar a resposta com clareza (código de status, tempo, JSON). Uma coleção é um grupo salvo dessas requisições. Exportá-la gera um arquivo JSON que qualquer pessoa pode importar para repetir seus testes. (Documentação do Postman: enviar sua primeira requisição, em inglês) Os nomes de menu abaixo podem variar um pouco na sua versão.

2. Configure a coleção uma vez

  1. Crie uma coleção nova chamada Salve Uma Música (treino).
  2. Na aba Authorization da coleção: tipo Basic Auth, usuário admin, senha secret. Cada requisição dentro dela usa Inherit auth from parent, então você digita o login uma única vez.
  3. Na aba Variables da coleção: adicione base_url = http://localhost:8080 e uma id_manual vazia. Em uma requisição você escreve {{base_url}}/musica/{{id_manual}} e o Postman preenche os valores.

3. Guarde um ID de uma resposta (o único script de que você precisa)

Uma música adicionada à mão não tem id do Deezer, então você faz o POST sem _id e o MongoDB inventa um. O RESTHeart o devolve no cabeçalho Location (veja a aba Headers da resposta). Para reutilizá-lo, abra a aba Scripts (versões antigas: Tests) da requisição POST abaixo e adicione:

const location = pm.response.headers.get("Location");
pm.collectionVariables.set("id_manual", location.split("/").pop());

4. As requisições

Crie-as nesta ordem. Para o corpo, abra a aba Body, escolha raw e JSON; assim o Postman envia o cabeçalho Content-Type correto para você. Clique em Send e compare o status com a tabela.

Método  URL                                Corpo                                           Esperado
PUT     {{base_url}}/musica                (nenhum)                                        201 (200 se já existe)
POST    {{base_url}}/musica                { "titulo": "Teste", "duracao": 100,            201
                                             "adicionado_manualmente": true, "vitorias": 0 }
GET     {{base_url}}/musica/{{id_manual}}  (nenhum)                                        200
GET     {{base_url}}/musica?pagesize=20    (nenhum)                                        200
PUT     {{base_url}}/musica/{{id_manual}}  { "titulo": "Teste 2", "duracao": 100 }         200
PATCH   {{base_url}}/musica/{{id_manual}}  { "$inc": { "vitorias": 1 } }                   200
DELETE  {{base_url}}/musica/{{id_manual}}  (nenhum)                                        204

Depois faça GET em {{base_url}}/musica/{{id_manual}} mais uma vez: agora deve dar 404. Confira o efeito de cada passo: depois do PUT, o adicionado_manualmente sumiu (o PUT substitui o documento inteiro), e o PATCH criou o vitorias de novo com o valor 1. É a armadilha da aula 2, agora visível.

Músicas importadas usam o número do Deezer como _id, então uma requisição por id delas precisa de ?id_type=NUMBER, por exemplo {{base_url}}/musica/518458172?id_type=NUMBER (aula 2, armadilha 4).

Atenção: o 201 não prova que seus dados foram salvos. Ele só significa "um documento foi criado". Se a aba Body estiver em none, ou em um tipo diferente de raw + JSON, o POST ainda retorna 201, mas guarda um documento vazio com um _id gerado, e cada novo envio adiciona mais um. Depois de qualquer POST, faça o GET e confira se os seus campos (titulo, duracao) estão lá. Se aparecerem documentos só com _id, apague-os (DELETE {{base_url}}/musica/<_id>), corrija a aba Body e envie o POST de novo.

5. Compare com a coleção do projeto

O repositório já tem a coleção completa em postman/colecao.json (requisições ao Deezer, as duas coleções, todos os métodos e um teste em cada status). Não exporte por cima dela. Em vez disso, use Import no Postman, escolha esse arquivo e compare com o que você montou. Dá para rodar tudo de uma vez com o botão Run da coleção.

O arquivo inclui o login admin / secret. Aqui não há problema, porque é o padrão público do RESTHeart.

6. Teste o que aprendeu

Por que configurar o Basic Auth na coleção em vez de em cada requisição?

O que faz {{base_url}} em uma URL?

Você faz DELETE de uma música e depois GET dela. O que espera?

Seu POST retornou 201, mas a lista mostra documentos só com _id. Qual é a causa mais provável?
