Frontend 5: Grid and the phone layout

Win: put the indicators, the charts, the song list and the form in grids, make the page work on a phone with one media query, test it in the browser's device mode, and push. This closes the "layout that works on the phone" requirement.

1. Grid in one line

Flexbox lines things up in one direction. Grid makes rows and columns (MDN: Grids). The line you will use most:

grid-template-columns: repeat(auto-fit, minmax(160px, 1fr));

Read it as: "as many columns as fit, each at least 160px wide, sharing the leftover space equally". On a wide screen that gives 5 columns; on a phone, 2 or 1. No media query needed. Two more pieces:

  • gap: space between cells, as in flexbox.
  • grid-column: 1 / -1: this child spans the whole row.

2. The tasks

Task 1, indicators. .indicadores: a grid of boxes, at least 140px each. .indicador: value on top (big, highlight color), label below (small, soft color), light background, rounded.

Answer key, task 1 
.indicadores {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(140px, 1fr));
  gap: 12px;
}
.indicador { display: flex; flex-direction: column; padding: 12px; background: var(--fundo); border-radius: var(--raio); }
.indicador-valor { font-size: 1.6rem; font-weight: 700; color: var(--destaque); }
.indicador-rotulo { font-size: .9rem; color: var(--texto-suave); }

Task 2, charts and the genre table. .graficos: the two charts side by side on wide screens (at least 280px each), one under the other on a phone. Give .grafico min-width: 0 so the chart can shrink. .tabela-generos: full width, a thin line under each row.

Answer key, task 2 
.graficos {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(280px, 1fr));
  gap: 16px;
  margin-top: 16px;
}
.grafico { margin: 0; min-width: 0; }
.grafico figcaption { text-align: center; font-size: .9rem; color: var(--texto-suave); }

.tabela-generos { width: 100%; border-collapse: collapse; }
.tabela-generos th, .tabela-generos td { padding: 6px 8px; text-align: left; border-bottom: 1px solid var(--borda); }

The charts are drawn by Chart.js inside the <canvas>; their colors are in CORES_GRAFICOS at the top of app.js, the only line of that file you may change.

Task 3, the song list. .lista-musicas: cards in a grid, at least 300px each; remove the list bullets and the default padding of the <ul>.

Answer key, task 3 
.lista-musicas {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(300px, 1fr));
  gap: 10px;
  padding: 0;
  list-style: none;
}

auto-fill instead of auto-fit: with only one or two songs (after a search), the cards keep their size instead of stretching across the row.

Task 4, the form. .form-musica: fields in a grid (at least 220px each). The error list and the buttons take a whole row each.

Answer key, task 4 
.form-musica {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(220px, 1fr));
  gap: 12px;
}
.form-erros, .form-botoes { grid-column: 1 / -1; }
.form-erros { margin: 0; color: var(--erro); }

3. The phone: one media query

A media query applies rules only when a condition is true, for example a screen narrower than 600px (MDN: media queries). Most of the page already adapts thanks to auto-fit and flex-wrap. Only three things need help:

Task 5. Below 600px: the two game options one under the other, each full width, with a smaller cover; the song list in a single column that is allowed to shrink.

Answer key, task 5 
@media (max-width: 600px) {
  .confronto-opcoes { flex-direction: column; }
  .opcao { width: 100%; max-width: none; }
  .opcao .capa { max-width: 120px; }
  .lista-musicas { grid-template-columns: minmax(0, 1fr); }
}

Why minmax(0, 1fr) and not just 1fr? A 1fr column never gets narrower than its content. The titles are kept on one line, so a long title would make the column wider than the phone and the page would scroll sideways. minmax(0, 1fr) lets the column shrink, and the title gets its "...".

4. Test it as a phone

  1. Open localhost:3000, press F12, then Ctrl+Shift+M (device mode). At the top, pick a phone such as iPhone 12 Pro (390px wide). (Chrome docs: device mode)
  2. Check each line:
    • No sideways scrolling anywhere on the page.
    • The menu fits (it may drop below the title).
    • Indicators in two columns; charts one under the other.
    • In a game, the options are stacked and both buttons are easy to tap.
    • Songs in one column, long titles with "...", buttons below each card.
    • Form fields one per row.
  3. Close device mode and check the desktop again: 3 cards per row, options side by side.

5. Final commit

git branch                    the asterisk must be on frontend
git status                    frontend/style.css (and index.html, if you changed it)
git add frontend/style.css frontend/index.html
git commit -m "style: grid, painel e layout no celular"
git push

Then on GitHub, switch the branch selector to frontend and check that your commits appear in the history with your name.

Frontend 5: Grid e o layout no celular

Objetivo: colocar os indicadores, os gráficos, a lista de músicas e o formulário em grids, fazer a página funcionar no celular com uma media query, testar no modo dispositivo do navegador e fazer push. Isso fecha o requisito "layout que funcione no celular".

1. Grid em uma linha

O flexbox alinha as coisas em uma direção. O grid faz linhas e colunas (MDN: Grids, em inglês). A linha que você mais vai usar:

grid-template-columns: repeat(auto-fit, minmax(160px, 1fr));

Leia assim: "quantas colunas couberem, cada uma com pelo menos 160px, dividindo igualmente o espaço que sobra". Em uma tela larga isso dá 5 colunas; no celular, 2 ou 1. Sem media query. Mais duas peças:

  • gap: espaço entre as células, como no flexbox.
  • grid-column: 1 / -1: esse filho ocupa a linha inteira.

2. As tarefas

Tarefa 1, indicadores. .indicadores: um grid de caixas, com pelo menos 140px cada. .indicador: valor em cima (grande, cor de destaque), rótulo embaixo (pequeno, cor suave), fundo claro, cantos arredondados.

Gabarito, tarefa 1 
.indicadores {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(140px, 1fr));
  gap: 12px;
}
.indicador { display: flex; flex-direction: column; padding: 12px; background: var(--fundo); border-radius: var(--raio); }
.indicador-valor { font-size: 1.6rem; font-weight: 700; color: var(--destaque); }
.indicador-rotulo { font-size: .9rem; color: var(--texto-suave); }

Tarefa 2, gráficos e a tabela de gêneros. .graficos: os dois gráficos lado a lado em telas largas (pelo menos 280px cada), um embaixo do outro no celular. Dê ao .grafico um min-width: 0 para o gráfico conseguir encolher. .tabela-generos: largura total, uma linha fina embaixo de cada linha.

Gabarito, tarefa 2 
.graficos {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(280px, 1fr));
  gap: 16px;
  margin-top: 16px;
}
.grafico { margin: 0; min-width: 0; }
.grafico figcaption { text-align: center; font-size: .9rem; color: var(--texto-suave); }

.tabela-generos { width: 100%; border-collapse: collapse; }
.tabela-generos th, .tabela-generos td { padding: 6px 8px; text-align: left; border-bottom: 1px solid var(--borda); }

Os gráficos são desenhados pelo Chart.js dentro do <canvas>; as cores deles ficam em CORES_GRAFICOS, no topo do app.js, a única linha desse arquivo que você pode mudar.

Tarefa 3, a lista de músicas. .lista-musicas: cartões em grid, com pelo menos 300px cada; tire os marcadores da lista e o padding padrão do <ul>.

Gabarito, tarefa 3 
.lista-musicas {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(300px, 1fr));
  gap: 10px;
  padding: 0;
  list-style: none;
}

auto-fill em vez de auto-fit: com só uma ou duas músicas (depois de uma busca), os cartões mantêm o tamanho em vez de esticar pela linha toda.

Tarefa 4, o formulário. .form-musica: campos em grid (pelo menos 220px cada). A lista de erros e os botões ocupam uma linha inteira cada.

Gabarito, tarefa 4 
.form-musica {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(220px, 1fr));
  gap: 12px;
}
.form-erros, .form-botoes { grid-column: 1 / -1; }
.form-erros { margin: 0; color: var(--erro); }

3. O celular: uma media query

Uma media query aplica regras só quando uma condição é verdadeira, por exemplo uma tela mais estreita que 600px (MDN: media queries, em inglês). Quase toda a página já se ajusta graças ao auto-fit e ao flex-wrap. Só três coisas precisam de ajuda:

Tarefa 5. Abaixo de 600px: as duas opções do jogo uma embaixo da outra, cada uma com a largura toda, e com a capa menor; a lista de músicas em uma coluna só, que tenha permissão para encolher.

Gabarito, tarefa 5 
@media (max-width: 600px) {
  .confronto-opcoes { flex-direction: column; }
  .opcao { width: 100%; max-width: none; }
  .opcao .capa { max-width: 120px; }
  .lista-musicas { grid-template-columns: minmax(0, 1fr); }
}

Por que minmax(0, 1fr) e não só 1fr? Uma coluna 1fr nunca fica mais estreita que o conteúdo dela. Os títulos ficam em uma linha só, então um título longo deixaria a coluna mais larga que o celular e a página rolaria para o lado. O minmax(0, 1fr) deixa a coluna encolher, e o título ganha o "...".

4. Teste como celular

  1. Abra localhost:3000, aperte F12 e depois Ctrl+Shift+M (modo dispositivo). No topo, escolha um celular como iPhone 12 Pro (390px de largura). (Documentação do Chrome: modo dispositivo, em inglês)
  2. Confira cada linha:
    • Nenhuma rolagem para o lado em nenhum ponto da página.
    • O menu cabe (pode descer para baixo do título).
    • Indicadores em duas colunas; gráficos um embaixo do outro.
    • Em uma partida, as opções ficam empilhadas e os dois botões são fáceis de tocar.
    • Músicas em uma coluna, títulos longos com "...", botões embaixo de cada cartão.
    • Campos do formulário um por linha.
  3. Feche o modo dispositivo e confira o computador de novo: 3 cartões por linha, opções lado a lado.
