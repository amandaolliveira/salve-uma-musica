Frontend 2: The frontend inside nginx

Win: explain how the frontend container serves your HTML and CSS, see an edit appear without restarting anything, and recognise three ways it breaks. This is the +1.0 extra point of the assignment, and the part you will explain in the demo. Needs base lesson 1.

1. What nginx does

nginx is a web server: it receives HTTP requests and answers with files from a folder (nginx beginner's guide). The official image nginx:alpine serves whatever is in /usr/share/nginx/html inside the container (Docker Hub: nginx). Our job is only to put frontend/ there.

2. The service, line by line

  frontend:
    image: nginx:alpine          # small official nginx image
    depends_on:
      - restheart                # start after the API
    ports:
      - "3000:80"                # localhost:3000 on your computer -> port 80 of nginx
    volumes:
      - ./frontend:/usr/share/nginx/html:ro                     # your files, read-only
      - ./nginx/default.conf:/etc/nginx/conf.d/default.conf:ro  # nginx settings (the proxy)

./frontend:/usr/share/nginx/html is a bind mount: a folder of your computer shown inside the container (Docker docs: bind mounts). It is not a copy, so when you save style.css, nginx already sees the new file. :ro means read-only: the container can read your files but never change them.

Compare with the database: dados-mongo is a named volume, a storage area managed by Docker. Here we want the opposite, your own folder, so you can edit it.

3. The nginx settings (nginx/default.conf)

location / {                     # any normal path: answer with a file
    root  /usr/share/nginx/html;
    index index.html;            # "/" means index.html
}
location /deezer/ {              # paths starting with /deezer/: ask Deezer
    ...
    proxy_pass $deezer;
}

The page needs Deezer's genre and chart lists, but Deezer does not allow browsers on other sites to read its answers (that rule is called CORS). So the page asks nginx at /deezer/..., and nginx asks Deezer and passes the answer back. The requests to the database go straight from the browser to localhost:8080 (RESTHeart allows it). You will not need to change this file.

4. Try it

In the repo folder, on your branch:

  1. Start and fill with data. docker compose up -d, open http://localhost:3000, go to Importar, import a genre, and play one short game. You need songs on screen to style them later.
  2. Live edit. Open frontend/style.css, add body { background: yellow; }, save, and reload the page (Ctrl+F5). The page turns yellow, with no restart. Delete that line and save.
  3. Read-only. Run: 
    docker compose exec frontend sh -c "echo teste > /usr/share/nginx/html/teste.txt"
    Expected: Read-only file system. That is the :ro.
  4. Port. In docker-compose.yml, change "3000:80" to "3001:80", save, run docker compose up -d. Now localhost:3001 works and 3000 does not. Change it back to 3000 and run docker compose up -d again.
  5. Wrong folder. Change ./frontend: to ./frontendx:, save, docker compose up -d, open localhost:3000: 403 Forbidden. Docker created an empty folder frontendx on your computer and nginx found nothing to serve. Change it back, docker compose up -d, and delete the frontendx folder.
  6. The proxy. Open localhost:3000/deezer/genre: Deezer's JSON, through nginx.

Finish with git status. Nothing should be listed as modified. If docker-compose.yml is, undo it with git restore docker-compose.yml and run docker compose up -d.

Frontend 2: O frontend dentro do nginx

Objetivo: explicar como o contêiner frontend serve o seu HTML e CSS, ver uma alteração aparecer sem reiniciar nada, e reconhecer três jeitos de quebrar. Esse é o ponto extra (+1,0) do trabalho, e a parte que você vai explicar na apresentação. Precisa da aula base 1.

1. O que o nginx faz

O nginx é um servidor web: ele recebe requisições HTTP e responde com arquivos de uma pasta (guia para iniciantes do nginx, em inglês). A imagem oficial nginx:alpine serve o que estiver em /usr/share/nginx/html dentro do contêiner (Docker Hub: nginx). O nosso trabalho é só colocar a pasta frontend/ ali.

2. O serviço, linha por linha

  frontend:
    image: nginx:alpine          # imagem oficial do nginx, pequena
    depends_on:
      - restheart                # sobe depois da API
    ports:
      - "3000:80"                # localhost:3000 do seu computador -> porta 80 do nginx
    volumes:
      - ./frontend:/usr/share/nginx/html:ro                     # seus arquivos, só leitura
      - ./nginx/default.conf:/etc/nginx/conf.d/default.conf:ro  # configuração do nginx (o proxy)

./frontend:/usr/share/nginx/html é um bind mount: uma pasta do seu computador mostrada dentro do contêiner (Documentação do Docker: bind mounts, em inglês). Não é uma cópia, então quando você salva o style.css, o nginx já enxerga o arquivo novo. O :ro quer dizer só leitura: o contêiner pode ler os seus arquivos, mas nunca alterá-los.

Compare com o banco: o dados-mongo é um volume nomeado, uma área gerenciada pelo Docker. Aqui queremos o contrário, a sua própria pasta, para você poder editar.

3. A configuração do nginx (nginx/default.conf)

location / {                     # qualquer caminho normal: responde com um arquivo
    root  /usr/share/nginx/html;
    index index.html;            # "/" quer dizer index.html
}
location /deezer/ {              # caminhos que começam com /deezer/: pergunta ao Deezer
    ...
    proxy_pass $deezer;
}

A página precisa das listas de gêneros e de músicas em alta do Deezer, mas o Deezer não deixa navegadores de outros sites lerem as respostas dele (essa regra se chama CORS). Então a página pergunta ao nginx em /deezer/..., e o nginx pergunta ao Deezer e devolve a resposta. As requisições ao banco vão direto do navegador para o localhost:8080 (o RESTHeart permite). Você não vai precisar mudar esse arquivo.

4. Experimente

Na pasta do repositório, na sua branch:

  1. Suba e coloque dados. docker compose up -d, abra http://localhost:3000, vá em Importar, importe um gênero e jogue uma partida curta. Você precisa de músicas na tela para estilizar depois.
  2. Edição ao vivo. Abra o frontend/style.css, acrescente body { background: yellow; }, salve e recarregue a página (Ctrl+F5). A página fica amarela, sem reiniciar nada. Apague essa linha e salve.
  3. Só leitura. Rode: 
    docker compose exec frontend sh -c "echo teste > /usr/share/nginx/html/teste.txt"
    Esperado: Read-only file system. É o :ro.
  4. Porta. No docker-compose.yml, troque "3000:80" por "3001:80", salve e rode docker compose up -d. Agora localhost:3001 funciona e a 3000 não. Volte para 3000 e rode docker compose up -d de novo.
  5. Pasta errada. Troque ./frontend: por ./frontendx:, salve, docker compose up -d e abra localhost:3000: 403 Forbidden. O Docker criou uma pasta vazia frontendx no seu computador e o nginx não achou nada para servir. Volte ao normal, docker compose up -d, e apague a pasta frontendx.
  6. O proxy. Abra localhost:3000/deezer/genre: o JSON do Deezer, passando pelo nginx.

Termine com git status. Nada deve aparecer como modificado. Se o docker-compose.yml aparecer, desfaça com git restore docker-compose.yml e rode docker compose up -d.
